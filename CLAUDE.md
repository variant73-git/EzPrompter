## O que é
**Uncraft** é uma extensão Chrome que funciona como um **design tool para a web** — o designer edita qualquer site visualmente, sem sair do browser. Slogan: "Design without borders".

Três frentes:
1. **Page Editor** — editor Figma-like: layers panel, inspector, spacing guides, edição visual in-place
2. **Canvas (web-shell)** — board Next.js estilo node-graph: clones de sites, assets, prompts, agente de chat orquestrando o grafo
3. **Image Remix** — reverse-engineer do prompt de qualquer imagem + geração inline via IA

## Posicionamento Estratégico
Uncraft é o único tool que **edita sites visualmente no browser** com controles de design tool (layers, inspector, spacing). Nenhum competidor faz isso: html.to.design leva pro Figma; same.new gera código React; ClonewebX exporta pra builders; CSS Pro edita CSS sem layers/inspector; CSS Peeper é read-only.

## Lições permanentes (destiladas dos checkpoints — valem sempre)
- ⭐ **Quando o Adilson diz "clone", é o ANIMADO (native)** — iter9 só por nome; screenshot→site é ferramenta de imagem. Medir o clone estático de um site animado é responder a pergunta errada ("será naturalmente impreciso"). E antes de otimizar o caminho que está na mão, perguntar **qual ferramenta a doutrina do produto designa para o trabalho** — o produto já tinha iter9 E native, e uma sessão inteira mediu fatiamento de screenshot (183).
- ⭐ **Tempo de modelo de visão é dominado pelo raciocínio invisível**, não pela escrita nem pelo prompt — effort low cortou 50-110s para 18-33s com saída do mesmo tamanho; o prompt maior foi o MAIS RÁPIDO no A/B histórico. E ±40% de variância na MESMA config → teto dimensionado por uma amostra é chute; dimensionar por percentil medido (183).
- ⭐ **Instrumento se valida CRUZADO e com controles** — o SSIM do produto reproduziu o do ffmpeg (implementação independente) com delta ≤0,0002; identidade, negativo e área lisa como controles. E **guarda sem teste nasce morta, 2ª e 3ª instâncias**: o aviso de área lisa nunca funcionou (`YLOW=` vs `YLOW:`), e um mock que devolve sempre `true` escondeu o early-return que engolia o pedido nominal (183).
- **`fetch` NORMALIZA o caminho antes de enviar** (`/../x` e `%2e%2e` viram `/x`) — teste de path-traversal via fetch dá verde sem nunca alcançar a guarda; pedir por SOQUETE CRU (181). E contenção de pasta compara CAMINHO REAL com separador incluído — `startsWith` cru deixa passar a pasta irmã, e symlink escapa sem realpath (181).
- **Guarda de SSRF valida CADA SALTO de redirect** — checar só o primeiro endereço não fecha nada: um host público responde 302 para link-local e `redirect:'follow'` vai atrás; `redirect:'manual'` + validação por salto + teto (182).
- **Refazer meio-certo é pior que nenhum** — a entrada de criação guarda a linha do momento da CRIAÇÃO (refazer ressuscita a versão velha por cima da editada); invalidar por "algo mudou" não vê conteúdo; e restauro `ON CONFLICT DO NOTHING` devolve 200 sem provar equivalência. Refazer confiável = histórico transacional before/after por operação (182).
- **"Não foi cobrado" só se afirma com código TIPADO do servidor** — só ele sabe se cancelou antes de cobrar; classificar pela mensagem confunde a desistência do navegador (que não prova nada) com cancelamento do servidor (182).
- **Entregável não mora em /tmp** — a limpeza entre sessões comeu uma rodada inteira de teste; artefato que o dono vai abrir vive em pasta durável do repo (183).
- ⭐ **Um anúncio único e sem confirmação é uma corrida esperando acontecer** — `runtime-ready` parte uma vez; na abertura fria o ouvinte já está lá (5,9s antes), ao recarregar o iframe vem do cache e fala 0,27s antes de alguém escutar. Quem depende do anúncio (aqui: reaplicar o que foi salvo) simplesmente nunca roda. Pior: um batimento promovia o estado para "pronto" **sem handshake nenhum**, então tudo *parecia* certo. Estado derivado de um evento que pode se perder precisa de um jeito de PEDIR o evento de volta (180).
- ⭐ **Identidade por POSIÇÃO não sobrevive a nada** — a animação era batizada pela posição na lista global do GSAP e 122 de 123 trocavam de nome ao recarregar (o site cria 184 numa carga e 189 na outra). Chave de identidade quer duas provas medidas: **unicidade** dentro da sessão e **estabilidade** entre sessões, com referência independente da própria chave (senão a medida é circular). E **nunca incluir na chave o campo que o usuário edita** — a identidade mudaria de nome no primeiro ajuste (180).
- ⭐ **Trocar código no lugar errado é silencioso** — o batismo da animação vinha do INVENTÁRIO do viewport, não da inspeção da seleção; como o nome fica guardado por objeto, quem chega depois só lê o cache e a minha troca ficou **inerte** (o identificador nem mudou). Quando um valor "não muda" depois de uma correção, rastrear quem o produziu de verdade (`console.log` com a pilha) em vez de reler o caminho que se supõe (180).
- ⭐ **Recusar não pode ser o mesmo que esquecer** — a recusa de reaplicar podava os patches do histórico, e o "Save changes" grava o histórico atual: o próximo salvamento destruiria o trabalho guardado. Toda poda de intenção confirmada precisa ser conferida contra o que a persistência grava depois (180, achado do Codex).
- **`CREATE TABLE IF NOT EXISTS` não acrescenta coluna** em tabela que já existe — schema que roda a cada boot precisa de `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` para bancos anteriores, senão o primeiro índice sobre a coluna nova derruba o boot inteiro. E **dividir .sql por ponto e vírgula cru parte ao meio todo `DO $$ … END $$`** — que é justamente a forma usada para "criar a trava só se ela não existir", ou seja, migrações com trava condicional nunca podiam ser aplicadas por esse caminho (180b).
- ⭐ **"Isto funciona?" se responde EXECUTANDO, não instrumentando** — quatro réguas seguidas mediram alinhamento e foram lidas como qualidade, custando horas de leitura do dono; `npm run dev:motion` + uma captura de tela respondeu em 20 minutos. Instrumento serve para "quanto", não para "existe". E número que não distingue deriva imperceptível de coisa quebrada é medida de alinhamento disfarçada de qualidade (179).
- ⭐ **Posição de rolagem NÃO é coordenada comparável** entre um site dirigido por JS e um clone sem JS: o original está sempre em algum estado de animação e o clone está congelado. Comparação de fidelidade exige **âncora por elemento** + braço de controle (o original contra ele mesmo) + verificação de que o recorte tem contraste (recorte liso é fundo, e comparar fundo com fundo dá 100% de diferença sem significar nada) (179).
- ⭐ **Uma regra que engole o caso geral** — `needsDeferredReconstruction` devolve `true` para QUALQUER referência de URL antes de checar `animatedDetected`, então o iter9 (que existia para clonar site animado SEM animação) virou o clone de tudo. Ao investigar "por que o caminho X está sendo usado", ler a ORDEM das guardas, não só a intenção declarada (179).
- ⭐ **Rigor sem modelo de ameaça vira esteira** — 6 das 13 rodadas de auditoria perseguiram um `Proxy` hostil cuja classe já se sabia não fechar. Antes de gastar rodada numa classe, perguntar **de quem é o dano** e **até onde ele chega**: quando a resposta é "o atacante estraga a si mesmo", fecha-se por ESCOPO, não por conserto. E **não oferecer escolha binária quando falta o fato que decide** — buscar o fato primeiro (178, Finding do Adilson).
- ⭐ **Apagar um teste deixa a suíte VERDE** — uma edição por fatia comeu um teste inteiro e nenhum vermelho apareceu; quem pegou foi a CONTAGEM (370→369). Conferir contagem depois de reescrever bloco de teste (178).
- ⭐ **Substituição que não casa passa silenciosa** — uma correção minha num doc nunca entrou e o commit afirmava que sim. Toda edição por `replace` precisa de asserção de que o alvo casou (178).
- **Uma obrigação corrigida em rodadas SEGUIDAS = instância, não regra** — a travessia caiu 2× e o TOCTOU 3× (restauração → instalação → leitura do pré-voo). O sinal é o reincidir; a regra certa era "nenhum seek roda enquanto a janela DECIDE ou MEXE em `vars`" (178).
- ⭐ **Zero sem controle é o modo de falha dominante** — três achados de uma auditoria de 13 rodadas foram eu concluindo "não disparou" onde não havia **oportunidade de disparo**: seek que não cruzava a fronteira, animação que já tinha começado, alvo que já estava no fim. Um zero só vale depois de um braço de controle > 0 na MESMA construção. Vale inclusive para a fronteira que se acabou de medir para corrigir o achado anterior (177).
- ⭐ **Inicializado ≠ reinicializado (GSAP inicializa lazy)** — abrir uma janela de supressão num alvo que NUNCA renderizou faz o zero provar "inicializou sem callback", não supressão. Pré-render **suprimido** inicializa sem rodar o `onUpdate` do site (medido) e é o jeito certo. E `invalidate()` no controle reintroduz o problema disfarçado: ele reinicializa, então mede outro caminho (177).
- ⭐ **Medir o estado final quando a pergunta é sobre o meio** — um teste que olha "quem sobrou no `vars` depois da janela" dá verde correto e esconde que a função instalada lá dentro DISPAROU. Contar instalação e disparo separadamente virou a diferença entre "a supressão é completa" e "a supressão tem furo" (177).
- ⭐ **Duas rodadas seguidas na mesma obrigação = está-se corrigindo instância, não enunciando regra** — a travessia da descendência caiu duas vezes (faltava descer no `.timeline`; depois faltava incluir a própria `.timeline` como nó). O sinal de alarme é o reincidir, não o achado (177).
- **`vars` do GSAP é a REFERÊNCIA do objeto do autor** — sites reusam um config entre animações, então mexer no `vars` de uma mexe na outra. Silenciar callbacks numa pode fazer a vizinha perder o dela, e restaurar não devolve o disparo perdido (177).
- ⭐ **Controle de sensibilidade também pode ser CONFUNDIDO** — mutar o objeto vivo move vários campos de uma vez (adicionar um filho muda `kids` E as durações), então o controle "prova" a sensibilidade sem provar nada. Prova campo a campo exige mutar a **REPRESENTAÇÃO** (cópias do registro que diferem em exatamente um campo), não o mundo. Corolário: num serializador canônico, **todo campo que participa da chave de ordenação precisa de controle posição-preservante** — senão o teste do campo vira teste da ordem (176).
- ⭐ **Duas provas sobre objetos diferentes não compõem um claim** — provar "recusa" com um descriptor e "não escreve" com outro não sustenta "recusa sem escrever". E **descriptor de patch nunca se fabrica**: ele sai da ownership PUBLICADA e é provado commitando num contexto suportado idêntico (mesma propriedade, mesma contagem de alvos) antes de ir ao caso sob teste — senão a recusa pode ser do descriptor inventado, não do caso (176).

Antes de afirmar ausência na publicação, dumpar a estrutura INTEIRA e procurar o campo, nunca inferir de um acesso que deu vazio (176).
- ⭐ **Witness que força um write model não cobre o classificador** — os DOIS instrumentos (witness Playwright + vitest) forçavam `absolute` e o defeito real morava no `additive-base` PUBLICADO; instrumentos independentes podem partilhar o mesmo ponto cego de fixação. Derivar sempre da publicação (`ownership.writeModel`) (173).
- ⭐ **Assinatura de prova completa = {estrutura, modificadores + DONO/local de autoria, targetScope, caminho}** — o MESMO par `repeat/repeatRefresh` muda de dono conforme autorado top-level (fachada) ou dentro de `stagger{}` (filho); prova de um escopo NUNCA promove outro; e tabela de FATOS separada de tabela de HIPÓTESES (10 rodadas do Sol pra chegar nisso) (173).
- **`progress(0)` não é o início** num tween repeat parado em iteração posterior — a fronteira renderiza como FIM da iteração anterior (totalTime 2.5 → progress(0) dá x=end); início semântico só por `totalTime(0, true)`. E probe de modificador exige o modificador ATIVO (`yoyo` sem repeat, `repeatRefresh` sem fronteira = verde vácuo) (173).
- ⭐ **Ao medir se X destrói Y, provar primeiro que Y ESTAVA VIVO** — a armadilha mais cara desta sessão. Concluí que "invalidate no pai apaga os edits por-filho" medindo um edit que nunca chegou a ser aplicado: observei não-aplicado seguir não-aplicado e li como destruição. ## Bugs conhecidos e padrões descobertos

### Padrão crítico: drag handlers em canvas mode precisam dos dois docs
**Problema**: Em canvas mode (`hostDoc !== targetDoc`), eventos mousemove/mouseup que originam DENTRO do iframe (target) NÃO bubble pro host doc. Drag handlers que escutam só `hostDoc.addEventListener('mousemove'/'mouseup')` ficam presos quando o cursor entra na área do iframe — mouseup nunca chega → drag em estado ghost-pressed → onMove dispara em loop conforme o cursor se move.

**Pior ainda**: `ev.clientX/Y` em eventos do iframe é em coords do **iframe viewport** (largura natural, ex 1280), enquanto `dragStartPos` capturado no mousedown do host está em coords do **host viewport**. Comparar os dois dá deltas absurdos.

**Solução** (editor.js):
- `bindDragOnBothDocs(move, up)` / `unbindDragOnBothDocs(move, up)` — registram em host + target quando docs são distintos.
- `eventToHostXY(ev)` — detecta `ev.view === targetWin` e converte iframe-coords → host-coords via `iframe.getBoundingClientRect() + scale`. Aplicar em TODA leitura de `ev.clientX/Y` em drag.
- Scale-aware delta: em zoom < 1, host-px delta dividido pelo `_scale` antes de virar valor CSS.
- Stash de elemento alvo (`var resizeEl = selectedEl`) no mousedown — closure pode virar null mid-drag.

**Aplicado em**: spacing-guide drag, corner-guide drag, selection-resize handles. ~6 outros handlers ainda só em host — migrar quando bug surgir.

### Padrão crítico: framework override (React/Framer/Hydrogen)
Sites com framework reativo reescrevem `style=""` e `className` no próximo render. Defesas cumulativas em `applyStyle._verifyApply`:
1. **Inline !important** (primeiro write) — vence especificidade normal
2. **ID rule !important** (`applyOverrideClass`) — vence quando framework rewrite `className`
3. **Sticky MutationObserver** (`startSticky`) — vence quando framework reescreve `style`. Dedup por `getCS === rec.value`. Disable após 5 fails em 2s.

Limite: full remount perde WeakMap. Em undo do `__cascade`, chamar `stopStickyForEl` antes de restaurar cssText.

### Padrão: dropdowns dentro do inspector devem ser `position:fixed` + body
`#rb-editor-inspector` tem `overflow:hidden` — dropdown `position:absolute` interno é clipado. Apend em `document.body` com `position:fixed` + reposição via `getBoundingClientRect(anchor)`. Cleanup em `updateInspector` e `deactivate`.

### Padrão: guide inline-edit input deve blurar em qualquer click fora
No mousedown capture do editor, se `e.target !== activeGuideInput`, chamar `.blur()` explicitamente. Comparar widgets deixa brechas.

### Padrão crítico: refactor `<select>` → `<input>` tem pontos cegos
Ao trocar select por input, `grep` TODAS as referências `.options`, `.selectedIndex`, `.multiple` antes de commitar.

### Padrão: position X/Y em elementos static
`position: static` ignora `left`/`top`. Antes de escrever, `ensurePositionable(el)` promove pra `relative`. Leitura: `readPosXY(el)` — nunca `r.left` (viewport).

### Padrão crítico: botões do editor
**TODOS os botões do editor UI: `mousedown` com `capture:true` + `stopImmediatePropagation()`.**

### CSS do editor: self-injection
`chrome.scripting.insertCSS` pode falhar silenciosamente. editor.js injeta o próprio CSS via `<link>` tag; arquivo em `web_accessible_resources`.

### CSS de sites interferindo
Sites com Webflow IX3/GSAP podem aplicar `opacity:0`/`visibility:hidden` aos painéis via seletores genéricos — editor.css protege com `!important`.

### rebuild.js v5 crashava o editor
Stylesheet extraction causava crash silencioso na inicialização. Revertido pra v4; re-implementar só como arquivo separado.

### Service worker e sendMessage
`toggleEditor` no background.js: `return true` + `sendResponse()` pra manter o worker acordado na injeção async.

### captureVisibleTab captura a aba ativa, não a do sender
background.js usa `sender.tab` e foca a aba antes de capturar.

### Chunked pipeline requer Tailwind CDN
`replacePageContent()` injeta o CDN no chunked path; viewport path usa inline styles.

### Prompt hardening degrada qualidade
Temperature baixa, topP, thinkingConfig, blocos "CRITICAL" e retry agressivo pioram o output do Gemini. Defaults + retry suave.

### FAB (Live Remix) removido
Causava bugs de display restore. Não reimplementar.
